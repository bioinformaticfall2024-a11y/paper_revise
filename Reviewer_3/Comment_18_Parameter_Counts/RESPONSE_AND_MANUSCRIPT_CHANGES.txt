EXACT MANUSCRIPT CHANGE — PARAGRAPH IMMEDIATELY AFTER TABLE 7
The computational requirements of the proposed models were analyzed by distinguishing trainable predictor parameters, frozen feature-extraction parameters, and separately trained auxiliary components, as summarized in Table 7. The DGraphDTA-style baseline contains 1,693,525 trainable parameters, whereas FGgraphDTA contains 1,924,525 parameters. The additional 231,000 parameters in FGgraphDTA arise from functional-group enrichment, which increases the ligand and protein input feature dimensions from 78 to 98 and from 54 to 74, respectively. In the implemented graph encoders, these changes affect the dimensions of the graph-convolutional layers and subsequent feature-projection layers.

PVgraphDTA contains 2,136,405 trainable predictor parameters and additionally incorporates a pretrained ResNet-101 visual feature extractor. The original 1,000-class classification layer of ResNet-101 is replaced with an identity operation, reducing the backbone parameter count from 44,549,160 to 42,500,160. During DTA training, the ResNet-101 backbone weights were frozen, while the graph encoders, visual projection layer, contrastive projection heads, and affinity-prediction layers remained trainable. Consequently, the frozen backbone parameters are excluded from the trainable DTA parameter count but included in the overall model parameter count.

The autoencoder contains 17,627,698 parameters and is trained separately to generate 128-dimensional protein structural representations. These latent representations are precomputed and remain fixed during DTA training. Therefore, the autoencoder parameters are included in the aggregate parameter count of the complete framework but are not included in the DTA model parameter count. The PVgraphDTA model, including its frozen visual backbone, contains 44,636,565 parameters, while the aggregate count across the predictor, visual backbone, and separately trained autoencoder is 62,264,263 parameters.

Although freezing ResNet-101 reduces the number of parameters requiring gradient updates during affinity-predictor training, the visual feature-extraction stage still introduces additional computational and memory requirements compared with the graph-only models. The reported parameter counts therefore distinguish model size from the number of parameters optimized during DTA training.

COMPLETE RESPONSE TO REVIEWER — USE ONLY AFTER APPLYING MANUSCRIPT EDITS AND VERIFYING THE HISTORICAL MODEL
We thank the reviewer for carefully examining the computational-complexity analysis and identifying inconsistencies in the reported parameter counts. We agree that the previous presentation did not clearly distinguish trainable predictor parameters, frozen feature-extraction parameters, and parameters of the separately trained autoencoder. We have therefore corrected Table 7 and clarified the contributions of the individual components.

First, the reviewer is correct that the standard torchvision ResNet-101 contains 44,549,160 parameters when its original 1,000-class classification head is present. Our implementation removes that fully connected classification head and replaces it with an identity operation, removing 2,049,000 parameters. Thus, the visual backbone actually used as a feature extractor contains 42,500,160 parameters, consistent with our previously reported approximate figure of 42.5 million. The backbone weights were frozen during DTA training, as confirmed by the author; these parameters were not optimized with the DTA predictor. We agree nevertheless that frozen parameters must be stated separately and included in the overall model inventory because they contribute to feature-extraction memory and compute requirements.

Second, our revised table distinguishes the 2,136,405 trainable PVgraphDTA predictor parameters, 42,500,160 frozen ResNet-101 backbone parameters, and 17,627,698 parameters of the independently trained autoencoder. The AE was used to generate precomputed 128-dimensional representations rather than being optimized jointly with the affinity predictor. Thus, the online DTA model comprises 44,636,565 parameters, whereas the aggregate architectural inventory across all components is 62,264,263 parameters. We agree that the previous "full pipeline" designation for the predictor-plus-AE subtotal was misleading because it excluded the ResNet backbone; this terminology has been replaced with explicit component definitions.

Third, we re-examined the DGraphDTA-style baseline and FGgraphDTA. Their previous identical count of approximately 1.925 million was incorrect. In the audited graph architecture, the baseline with 78-dimensional ligand and 54-dimensional protein node features contains 1,693,525 parameters, whereas the full FGgraphDTA with corresponding 98- and 74-dimensional features contains 1,924,525, a difference of 231,000. The increase affects multiple graph-convolutional and feature-projection layers because their widths depend on input_dim, not only the first convolution. We have updated Table 7 and clarified the relevant graph-encoder dimensions in the architecture description.

These changes correct the parameter accounting and distinguish trainable model size, frozen feature-extraction size, and separately trained preprocessing components without changing the reported experimental predictions.
